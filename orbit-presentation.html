Slide 3 of 8 — Security model
Security invariants
Private keys never touch disk
Ed25519 keys are decrypted from the vault into process memory for the lifetime of one SSH connection, then GC'd. The Go SSH client accepts an in-memory ssh.Signer — no temp files needed.
Secret values never appear in argv
Container secret_env maps env-var name → vault key. The value is placed in the docker subprocess's environment. Docker receives a bare -e NAME flag — not -e NAME=value. Invisible to ps.
Vault is encrypted at rest
Argon2id derives the AES key (salt=32B, m=64MiB, t=3, p=4 — ~300ms). Fresh 12-byte IV per write. Auth tag detects tampering. Derived key never persisted.
Audit log records metadata only
Tool handlers call envNames() to extract only key names, never values. cred_list and key_list return names and metadata — never plaintext secrets.

Multi-distro provisioner
A single POSIX sh script auto-detects the package manager and init system:
aptapkdnfyumzypperpacman
systemdOpenRCrunit
No cloud-init — OrbStack only ships it for Debian/Ubuntu. Alpine, Fedora, and Arch all work with the script (ADR-003).
Why direct SSH, not the multiplexer
OrbStack's 127.0.0.1:32222 multiplexer uses a single host key and ignores per-VM authorized_keys. Using it collapses all VM credentials onto one identity. Orbit dials <vm>.orb.local:22 directly so each VM keeps its own keypair (ADR-002).
